# Core 2.8.0 + القالب 2.7.15 — الكتّاب من فريق العمل، النشر المباشر، ومراجعة الأمان والسرعة والفهرسة

**الحزمتان تغيّرتا:** ارفع Core أولًا ثم القالب، بـ«استبدال الحالي بالمرفوع». هذه آخر مرة يدويًا: من 2.8.0 أنشر أنا مباشرة بعد ربط الموقع.
**ما لم يتغير:** التصميم والنصوص وH1 والميتا وcanonical وhreflang (60 رابطًا 200، بلا أخطاء PHP، والسكيما بلا أخطاء على نسخة الاختبار).

## 1. الكتّاب = فريق العمل
- كل عضو يكتب يُربط بحسابه في ووردبريس من «فريق العمل ← العضو ← حساب الكاتب في ووردبريس».
  - **الربط موجود من قبل.** الجديد أن أي رابط للكاتب يذهب لصفحته في الفريق: الرابط الذي يبنيه ووردبريس، وRank Math، والخلاصة (RSS).
- **أرشيفات الكتّاب:** `/author/اسم-الحساب/` و`?author=رقم` تحويل 301 لصفحة العضو، أو للمدونة إن لم يكن الحساب مرتبطًا. خلاصات الكتّاب تحويل لخلاصة الموقع.
  - هذا يمنع أيضًا كشف أسماء دخول الحسابات (كان `/?author=1` يعرض «admin»).
- **في المقال:**
  - «بقلم» يعرض اسم العضو بخط ورابط لصفحته (`rel="author"`).
  - Rank Math «Written by» يعرض اسم العضو بدل اسم الحساب.
  - السكيما: `author` = Person صفحة العضو.
  - صفحة العضو تعرض مقالاته.
- **عضو محذوف أو مخفي:** لا يُربط به أي مقال (لا روابط مكسورة بعد حذف محمد حسن). يُنسب المقال لحساب كاتبه.
- **حقل «حساب الكاتب»:** للمحرر والمدير فقط، فلا يستطيع كاتب أن ينسب لنفسه مقالات غيره.
- **قائمة الحسابات عبر REST** (`/wp-json/wp/v2/users`): مغلقة للزوار. المحرر يعمل كما هو.

## 2. النشر المباشر (Core: `inc/remote.php`، والأداة `tools/deploy.sh`)
- **مسارات REST** تحت `seohouse/v1`:
  - تقرير الموقع؛
  - النشر والتراجع؛
  - ربط الكتّاب ونقل المقالات؛
  - إعادة عدّ الأقسام.
- **من يستطيع:** مدير فقط، بنفس صلاحيات رفع القالب أو الإضافة من لوحة التحكم، وعبر «كلمة مرور تطبيق». حذف كلمة المرور يُنهي الوصول فورًا.
- **قبول الحزمة:** فقط حزمتا `seohouse` و`seohouse-core`، بعد مطابقة sha256 وفحص بنية الـZIP.
- **خطوات النشر:**
  1. نسخة احتياطية ZIP من الحالية (خارج مجلد upgrade، ومحجوبة عن الويب على Apache/LiteSpeed).
  2. تثبيت كـ«استبدال الحالي بالمرفوع» ثم تفعيل.
  3. تفريغ الكاش: LiteSpeed وWP Rocket وW3TC وSuper Cache وSiteGround وAutoptimize وWP Fastest Cache وopcache.
  4. طلب الصفحة الرئيسية: **إن أعادت خطأ 5xx تُعاد النسخة السابقة تلقائيًا.**
- **نقل المقالات لكاتب:**
  - يغيّر الكاتب فقط، دون تغيير تاريخ التعديل أو الرابط أو المحتوى.
  - يزيل «الكاتب من فريق العمل» المحدد يدويًا.
  - له وضع تجربة يعرض ما سيتغير قبل التنفيذ.
- **مجرَّب على نسخة الاختبار:**
  - نشر Core والقالب.
  - رفض بصمة خاطئة، وحزمة خاطئة، وطلب بلا دخول، وحساب «كاتب».
  - قالب مكسور عمدًا تراجع تلقائيًا والموقع 200.
  - التراجع اليدوي للقالب وCore.

### خطوات الربط (مرة واحدة)
1. ارفع `seohouse-core.zip` (2.8.0) ثم `seohouse-theme.zip` (2.7.15) يدويًا كالمعتاد.
2. «المستخدمون ← أضف جديد»: حساب خاص للنشر (مثل `claude-deploy`)، دوره مدير، بكلمة مرور قوية.
3. افتح الحساب ← «كلمات مرور التطبيقات» ← اسم «Claude» ← «إضافة» ← انسخ كلمة المرور (تظهر مرة واحدة).
4. على جهازك، من أي صفحة في المتصفح: افتح Console واكتب
   `"Basic " + btoa("claude-deploy:كلمة-مرور-التطبيق")`
   وانسخ الناتج.
5. في إعدادات بيئة Claude Code (قائمة البيئة أعلى الجلسة ← Edit):
   - **Network access ← Allowed domains:** أضف `seohouse.agency`.
   - **Network secrets:** المضيف `seohouse.agency`، والهيدر `Authorization`، والقيمة ناتج الخطوة 4.
   - كلمة المرور لا تُكتب في المحادثة ولا في الكود.
6. ابدأ جلسة جديدة. أول ما أفعله: `tools/deploy.sh site` للتأكد من الاتصال.
   - إن ظهر 401 مع أن البيانات صحيحة، فالاستضافة تحذف هيدر Authorization. الحل سطر في `.htaccess` نضيفه معًا.

### ما سأنفذه على الموقع بعد الربط
1. ربط عضو «ياسر» بحسابه في ووردبريس، وإنشاء الحساب إن لم يكن موجودًا.
2. نقل كل المقالات الحالية لاسمه: تجربة أولًا ثم تنفيذ.
3. حذف «محمد حسن» من فريق العمل (إلى سلة المهملات، قابل للاسترجاع).
4. إعادة عدّ الأقسام، ومراجعة تقرير الفهرسة (القائمة في القسم 4).

## 3. إصلاحات من مراجعة الأمان (لا شيء حرج أو عالي الخطورة)
| المشكلة | الإصلاح |
|---|---|
| بحث الموقع يطابق كلمات داخل المحتوى المحمي بكلمة مرور للزوار | شرط ووردبريس نفسه أُعيد، والملخص لا يظهر للمحمي |
| ملفات حزمة المحتوى JSON (فيها مسودات مقالات ونصوص غير منشورة) قابلة للتنزيل | Core يكتب `.htaccess` في مجلده يمنع json/md/txt/zip، ويختبر نفسه: إن سبّب خطأ في الخادم يحذفه |
| نموذج الحجز يقبل طلبًا بلا توقيت النموذج (بوتات) | الطلب بلا `ts` ولا `elapsed` يُرفض. النموذجان (مع JavaScript وبدونه) يعملان كما هما |
| رد «طلبك مسجل» يكشف مرجع طلب شخص آخر | لم يعد يُرجع المرجع عند التطابق بالمحتوى |
| كشف أسماء الحسابات من أرشيف الكاتب | تحويل 301 (القسم 1) |
| كاتب يستطيع ربط ملف عضو بحساب المدير | الحقل للمحرر والمدير فقط |

**ملاحظات للمتابعة (لم تُغيَّر):**
- حد الطلبات لكل IP يحتاج قراءة IP الزائر الحقيقي إن كان الموقع خلف Cloudflare.
- يُنصح بـ Turnstile إن زاد السبام.
- تصدير الإعدادات يحوي رمز Calendly نصًا.

## 4. السرعة والفهرسة
**أُصلح:**
- **روابط «افتح التقرير بالحجم الكامل» المكسورة** (`http://uploads/...`) في 5 صفحات: /services/seo/ksa/ وegypt وuae و/sectors/ecommerce/ و/sectors/health/. صارت رابط ملف الصورة نفسها.
- **«منع الفهرسة» من سيو هاوس** (مثل صفحة الشكر) كان يُتجاهل مع Rank Math قبل «نقل السيو إلى Rank Math». الآن noindex وخارج خريطة الموقع.
- **تحميل الخطوط المسبق:** من 4 ملفات (~158 KB) إلى 2 (العناوين والنص). الأوزان الأخرى تُحمَّل عند الحاجة.
- **شعار السكيما:** كان 290×68 (أقل من 112 بكسل التي يطلبها Google). صار نسخة 1400×328 من نفس الشعار الأزرق. الهيدر بلا تغيير.

**يحتاج فحصًا على الموقع الحقيقي** (التقرير يكشفه فورًا بعد الربط؛ نسخة الاختبار لا تمثله):
- «الإعدادات ← القراءة»: الصفحة الرئيسية = «الرئيسية» وصفحة المقالات = «المدونة».
- خريطة الموقع تحوي دراسات الحالة والفريق.
- أعداد الأقسام صحيحة، حتى لا يُمنع قسم فيه مقالات من الفهرسة.
- نوع البيئة production، والرابط ليس `/new/`، و«منع محركات البحث» غير مفعّل، ولا يوجد `robots.txt` ملف أو هيدر X-Robots-Tag.
- وصف الميتا لصفحة السيو والرئيسية.
- تحويل `/services/seo/stores-seo/` ← `/sectors/ecommerce/` موجود في «التحويلات».
- دراسة الحالة «قطاع التعليم والتدريب» رابطها `/results/تستتست/` (من الموقع القديم). يُفضل تغيير الرابط؛ ووردبريس يحوّل القديم تلقائيًا.

**توصيات للاستضافة:** ضغط Brotli/gzip (HTML من ~210 KB إلى ~30 KB)، وكاش صفحات، وكاش طويل للخطوط والصور، وتحويل واحد إلى https بدون www، وHTTP/2.

**توصيات لم تُنفذ** (تمس التصميم أو تحتاج قياسًا على الموقع الحقيقي):
- نقل CSS المشترك (~63 KB مكرر في كل صفحة) لملف خارجي مخزّن.
- حركة ظهور الهيرو تبدأ من شفافية 0 (تؤخر LCP حتى 0.7 ث).
- إيقاف الحركات المستمرة خارج الشاشة.
- نبذات حقيقية لصفحات الفريق (محتوى رقيق حاليًا).
- توحيد فاصل العناوين في Rank Math.
