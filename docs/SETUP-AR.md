# دليل التركيب — موقع سيو هاوس على ووردبريس

هذا الدليل لمن يركّب الموقع على بيئة تجريبية (Staging) أو على الخادم النهائي. لا تنفّذ أي خطوة على الموقع الحالي المنشور قبل اعتماد النسخة التجريبية.

## 1. المتطلبات

| العنصر | الحد الأدنى |
|---|---|
| ووردبريس | 6.5 أو أحدث (تم الاختبار على 7.1) |
| PHP | 8.1 أو أحدث، مع امتداد GD أو Imagick يدعم WebP |
| قاعدة البيانات | MySQL 8 أو MariaDB 10.6 |
| إضافة الحقول | **Advanced Custom Fields** — الإصدار المجاني 6.x من مستودع ووردبريس يكفي (اختُبر على 6.8.10) |
| البريد | إضافة SMTP موثوقة (مثل WP Mail SMTP أو FluentSMTP) لإرسال إشعارات طلبات الاستشارة |

> **ACF المجانية تكفي.** لا يستخدم الموقع أي حقل من ميزات ACF PRO: الأقسام مجموعات (Group) مجانية، والعناصر المتكررة نوع حقل من SEO House Core يحفظ كل عنصر سجلًّا منظمًا، والإعدادات شاشة ووردبريس تحفظ بواجهات ACF. التفاصيل في `acf-free-path.md`. الحزم لا تحتوي أي إضافة مدفوعة أو مفتاح ترخيص. لم يُختبر ACF PRO لعدم توفر ترخيص؛ لا يعتمد الموقع على أي ميزة خاصة به.

## 2. محتويات الحزمة

| الملف | ما هو | أين يُرفع |
|---|---|---|
| `seohouse-theme.zip` | الثيم (قوالب PHP مطابقة للتصميم) | المظهر ← القوالب ← إضافة جديد ← رفع |
| `seohouse-core.zip` | إضافة **SEO House Core**: أنواع المحتوى، الحقول، الإعدادات، النماذج، SEO وSchema، أداة التجهيز | الإضافات ← أضف جديد ← رفع |
| `seohouse-content.zip` | حزمة المحتوى: نصوص التصميم، الصور، القوائم، الإعدادات | سيو هاوس ← تجهيز المحتوى |

يمكن إعادة بناء الحزم من المستودع بالأمر: `tools/package.sh` (تُنشأ في `dist/`).

## 3. خطوات التركيب

1. ثبّت ووردبريس جديدًا (بلا محتوى الموقع القديم) واضبط لغة الموقع على العربية.
2. من **الإضافات ← أضف جديد** ابحث عن **Advanced Custom Fields** (من WP Engine) ثم ثبّتها وفعّلها.
3. ارفع `seohouse-core.zip` وفعّل الإضافة.
4. ارفع `seohouse-theme.zip` وفعّل الثيم.
5. افتح **إعدادات سيو هاوس ← تجهيز المحتوى**:
   - ارفع `seohouse-content.zip`.
   - اضغط **تشغيل تجريبي (بدون كتابة)** وراجع السجل: لا يجب أن يظهر «فشل».
   - اضغط **تجهيز / استكمال الناقص**.
   - اضغط **مطابقة القيم مع التصميم**. النتيجة المطلوبة: «القيم مطابقة للتصميم».
6. افتح **الإعدادات ← الروابط الدائمة** واضغط «حفظ» مرة واحدة دون تغيير (لتحديث قواعد الروابط على الخادم).

### بديل عبر سطر الأوامر (WP-CLI)

```bash
wp plugin install advanced-custom-fields --activate
wp plugin install seohouse-core.zip --activate
wp theme install seohouse-theme.zip --activate
unzip seohouse-content.zip -d /tmp/sh
wp seohouse import --source=/tmp/sh/content-pack --dry-run   # تجربة وعرض السجل
wp seohouse import --source=/tmp/sh/content-pack             # التنفيذ
wp seohouse verify                                           # فحص المطابقة
wp seohouse status                                           # حالة آخر تجهيز
```

## 4. سلوك أداة التجهيز (مهم)

- **لا تعمل تلقائيًا** عند تفعيل الإضافة أو فتح أي صفحة؛ تعمل فقط بطلب صريح من الشاشة أو من WP-CLI.
- **قابلة للتكرار بأمان:** تشغيلها مرة ثانية لا ينشئ نسخًا مكررة (كل عنصر مربوط بمفتاح مصدر ثابت).
- **لا تستبدل تعديلات المحرر:** كل حقل يُحفظ مع بصمة قيمته. إذا عدّله المحرر لاحقًا يظهر في السجل «محمي» ولا يُستبدل. الخيار `--force` وحده يستبدل، ويُستخدم بحذر.
- «تحديث ما لم يُعدَّل» (`--update`) يطبّق تغييرات الحزمة الجديدة على الحقول التي لم يعدّلها المحرر فقط.
- `--only=pages|team|cases|posts|menus|options` يحصر التجهيز في جزء واحد.
- المسارات الموجودة مسبقًا (صفحة بنفس الرابط أنشأها شخص آخر) لا تُمس، وتظهر في السجل «محمي».

## 5. ما يُنشأ كمسودة ولا يُنشر تلقائيًا

- **سياسة الخصوصية** و**الشروط والأحكام**: التصميم يحتوي نصًا مؤقتًا «[يُضاف النص القانوني المعتمد قبل النشر]». أضف النص القانوني المعتمد ثم انشر.
- دراستا الحالة **organic-revenue-growth** و**medical-search-growth**: بياناتهما غير مكتملة في التصميم، فأُنشئتا كمسودة مع noindex.
- روابط القوائم التي تشير إلى محتوى غير منشور تُخفى تلقائيًا حتى يُنشر.

## 6. بعد التركيب

1. **البريد:** اضبط SMTP، ثم أرسل طلبًا تجريبيًا من نموذج الحجز وتأكد من وصول الإشعار. في **طلبات الاستشارة** يظهر عمود «الإشعار»: «أُرسل» أو «فشل الإرسال».
2. **مستلمو الطلبات:** إعدادات سيو هاوس ← الاستشارة ← «بريد استلام الطلبات».
3. **أداة الحجز (Calendly أو بديلها):** إعدادات سيو هاوس ← الاستشارة ← «أداة الحجز» و«رابط التضمين». بدون رابط، تعرض الخطوة الثانية رسالة استلام فقط (لا تقويم وهمي).
4. **Google Tag Manager / GA4 / Search Console:** إعدادات سيو هاوس ← التكاملات. لا يُحمَّل أي كود تتبع قبل إدخال المعرّف، ولا يُحمَّل للمحررين المسجلين.
5. **التقييمات (Trustindex):** ضع الكود المختصر في «التكاملات». قبل ذلك تظهر بطاقات «مثال» فقط، ويمكن إخفاؤها بالكامل.
6. **بيئة الموقع:** على الخادم النهائي عرّف `define( 'WP_ENVIRONMENT_TYPE', 'production' );`. أي بيئة غير «production» تُخرج `noindex` تلقائيًا لكل الصفحات، حتى لا تُفهرس النسخة التجريبية.
7. **التخزين المؤقت والضغط:** فعّل ضغط gzip/brotli وذاكرة المتصفح للملفات الثابتة على الخادم أو عبر إضافة كاش. قياسات الأداء في `docs/qa-report.md` أُجريت مع ضغط HTML.
8. **إضافة SEO (اختياري):** إذا فُعّلت Rank Math أو Yoast أو SEOPress أو AIOSEO، تتوقف الإضافة عن إخراج العنوان والوصف وcanonical وSchema، حتى لا يتكرر الإخراج. حقول «عنوان SEO» و«الوصف» تُمرَّر إلى Rank Math/Yoast حيث يدعمان ذلك.

## 7. قبل الإطلاق: الروابط المنشورة

كل رابط منشور في الموقع الحالي (53 رابطًا من خرائط الموقع والروابط الداخلية) مسجّل في `data/legacy-urls.json` داخل حزمة المحتوى، ومراجَع في `legacy-url-map.md`. شغّل قبل الإطلاق:

```bash
wp seohouse launch-check            # كل رابط منشور يجب أن يعطي 200 أو 301 إلى صفحة 200
```

أي سطر FAIL يعني رابطًا منشورًا سيتحول إلى 404؛ حاليًا الأسطر المتبقية هي المسودات التي تنتظر الاعتماد والنشر (المقالات الثلاث والصفحتان القانونيتان). التحويلات تُدار من **إعدادات سيو هاوس ← التحويلات**، وتعمل فقط عندما لا توجد صفحة منشورة على الرابط القديم.

وصف البحث المقترح للصفحة الرئيسية وصفحة خدمة السيو والتصنيفين موجود في `data/seo-proposals.json`. بعد اعتماده:

```bash
wp seohouse apply-proposals --dry-run   # معاينة
wp seohouse apply-proposals             # يملأ الحقول الفارغة فقط
```

## 8. الروابط الدائمة المعتمدة

تُضبط تلقائيًا في أول تجهيز (إن كانت إعدادات ووردبريس الافتراضية لم تُغيَّر):

| النوع | الرابط |
|---|---|
| المقالات | `/blog/%postname%/` |
| تصنيفات المدونة | `/blog/category/<slug>/` |
| دراسات الحالة | `/results/<slug>/` |
| أعضاء الفريق | `/team/<slug>/` |
| البحث | `/?s=` (الرابط `/search/` يعيد 404) |

القائمة الكاملة للمسارات في `docs/routes-manifest.json` و`docs/page-inventory.csv`.

## 9. الترحيل إلى الخادم النهائي

- الطريقة الأنظف: تكرار الخطوات 1–6 على الخادم النهائي بنفس الحزم، ثم نقل التعديلات التحريرية المعتمدة يدويًا. بدلًا من ذلك انقل قاعدة البيانات مع أداة استبدال روابط تدعم البيانات المسلسلة (مثل `wp search-replace`).
- **لا تستورد** قاعدة بيانات الموقع القديم ولا وسائطه ولا ثيمه.
- إعدادات سيو هاوس ← إدارة الإعدادات تتيح تصدير الإعدادات واستيرادها كملف JSON مع معاينة قبل التطبيق.

## 10. للمطورين

- المصدر الوحيد للتصميم هو ملفات التصميم المعتمدة. `tools/design-import/convert.js` يولّد قوالب الأقسام (`sections/<page>/*.php`) ومجموعات الحقول (`acf-json/group_sh_page_*.json`) وحزمة المحتوى. `core-groups.js` يولّد المجموعات الثابتة.
- الملفات التي تحتوي السطر ` * @sh-manual` في رأسها تُصان يدويًا ولا يعيد المولّد كتابتها: عناصر التبويبات الأربعة ونموذج صفحة التواصل.
- `tools/dev-reset.sh <design-dir>` يعيد بناء كل شيء محليًا من الصفر (مع ACF المجانية).
- `tools/qa/admin-edit-test.js` يختبر التحرير عبر لوحة التحكم الحقيقية (أقسام، قوائم، إعدادات، حفظ وإعادة عرض).
- `tools/qa/crawl.js` يزحف على الموقع كاملًا ويفحص الروابط والأصول وخريطة الموقع وظهور المسودات.
- `tools/qa/compare.js` يقارن لقطات التصميم بلقطات ووردبريس بعرض 1440 و768 و390.
- `tools/docs/build-docs.js --wp <url>` يعيد توليد ملفات الجرد في `docs/`.
- حفظ تعديلات الحقول من لوحة التحكم إلى `acf-json` معطّل افتراضيًا، ويُفعّل محليًا فقط عبر `define( 'SH_ACF_SAVE_JSON', true );`.
