## 2. قرارات تقنية

- **مسار الحقول:** Secure Custom Fields (مجانية، نفس واجهة ACF، تشمل Repeater وFlexible Content وصفحة الإعدادات). يعمل الموقع أيضًا مع ACF PRO إن وُجدت رخصة. ACF المجانية وحدها لا تكفي، وتظهر رسالة تنبيه في لوحة التحكم. لا يوجد نظام حقول موازٍ.
- **تحويل التصميم:** مولّد (`tools/design-import`) يعرض صفحات التصميم ويحوّل كل قسم إلى قالب PHP ومجموعة حقول وقيم افتراضية، فلا تُلصق الصفحات ككتل HTML ولا تُعرض عبر iframe. كل نص وصورة ورابط حقل. العناصر المكررة Repeater، والأرقام التسلسلية تُحسب من ترتيب الصفوف.
- **ألوان الهوية** متغيرات CSS (`--sh-*`) قابلة للتعديل من الإعدادات للأدوار المعتمدة فقط.
- **CSS داخل الصفحة** لكل قالب (لا ملفات تمنع العرض)، **وخطوط محلية**، **وWebP تلقائي** للصور.
- **خمسة أقسام تُصان يدويًا** (`@sh-manual`): تبويبات «نتائج» و«مراحل العمل» في خدمة السيو، وقطاعات مصر، وفرص الإمارات، ونموذج صفحة التواصل. التبويبات غير النشطة غير موجودة في DOM التصميم، فبُنيت من بيانات التصميم نفسها بحقل واحد لكل عنصر (سطح المكتب والجوال من نفس القيم).
- **البيئات غير الإنتاجية** تُخرج noindex تلقائيًا.

## 4. ينتظر قرارًا أو محتوى معتمدًا

| البند | المطلوب |
|---|---|
| وصف SEO للرئيسية وخدمات السيو | لا يوجد وصف في التصميم المعتمد؛ لم يُكتب وصف من عندنا |
| `/services/seo/stores-seo/` | موجودة في الموقع الحالي ولا تصميم لها — لم تُنشأ (تحويل 301 أو تصميم) |
| `/blog/how-to-build-backlinks-correctly/` ومقال آخر | موجودان في الموقع الحالي بلا محتوى في التصميم — لم يُنشآ |
| لقطات معرض دراسات الحالة | لقطات التصميم مكررة بين الحالات؛ مخفية حتى تُرفع لقطات موثقة وتُفعّل «لقطة موثقة لهذه الحالة» |
| أداة الحجز (Calendly أو بديل) | تحديد المزوّد والرابط؛ حتى ذلك تعرض الخطوة الثانية رسالة استلام فقط |
| Trustindex | الكود المختصر؛ حتى ذلك تظهر بطاقات «مثال» معلنة (يمكن إخفاؤها) |
| الهاتف ورابط واتساب | لا يظهران قبل إدخال رقم معتمد |
| أيقونة الموقع (Favicon) | غير موجودة في التصميم؛ تُضاف من «تخصيص ← هوية الموقع» |
| نصوص المقالين الإضافيين في بطاقات الرئيسية | التصميم يعرض 3 بطاقات عيّنة؛ الموقع يعرض المقالات المنشورة فعليًا (مقال واحد حاليًا) |

## 5. انحرافات مقصودة عن التصميم

انظر `qa-report.md` §5. أهمها:
- شفافية أرقام الخطوات في صفحة سلة رُفعت من 0.5 إلى 0.56 (حد التباين 3:1).
- عنوان بطاقة المقال في الرئيسية وجدول محتويات المقال يأتيان من المقال الحقيقي.
- رابط «بناء الروابط» في فوتر الرئيسية وُحّد إلى «السيو الخارجي» كبقية الصفحات.

## 6. قيود التزمنا بها

- لم يُستخدم أي محتوى أو ثيم أو قاعدة بيانات أو وسائط من الموقع القديم. استُخدم الموقع المنشور **للمسارات فقط** (slug المقال من خريطة الموقع).
- لم يُمس الموقع المنشور، ولم يُنشر شيء عليه.
- لا أسرار أو مفاتيح في المستودع أو الحزم، ولا إضافات مدفوعة.
- لم تُختلق أرقام أو تقييمات أو تواريخ؛ الأمثلة موسومة «مثال».

## 7. الخطوات التالية المقترحة

1. تركيب الحزم على بيئة Staging حسب `SETUP-AR.md` ومراجعة المحتوى.
2. إدخال المحتوى المعتمد للبنود في §4، ونشر الصفحات القانونية.
3. ضبط SMTP وأداة الحجز والتكاملات.
4. قياس Lighthouse على الاستضافة النهائية بعد تفعيل الكاش.
5. خطة تحويلات 301 للمسارات القديمة غير الموجودة في التصميم قبل الإطلاق.
