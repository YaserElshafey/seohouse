ما نُفِّذ للوصول لهذه النتائج:
- CSS كل صفحة (~25–35 KB، ≈6 KB مضغوط) يُطبع داخل الصفحة: لا ملفات تمنع العرض.
- خطوط محلية WOFF2 بـ`font-display: swap` وتحميل مسبق لخطوط العربية فوق الطيّة.
- تحويل الصور إلى WebP عند الرفع (والتجهيز)، ومقاسات فرعية WebP مع `srcset`.
- شعار الهيدر WebP بحجم 5 KB مع `fetchpriority="high"`؛ شعارات العملاء بمقاس متوسط و`loading=lazy` وأولوية منخفضة.
- سكربت واحد (`site.js` ~19 KB) مؤجل؛ لا jQuery ولا مكتبات خارجية؛ لا CSS لمحرر المكوّنات في قوالب التصميم.
- أكواد التتبع لا تُحمَّل إلا بعد إدخال معرّفها، ولا تُحمَّل للمحررين.

ملاحظة: CLS في صفحة عضو الفريق (0.092) ناتج عن تبديل الخطوط اللاتينية (LinkedIn، الأرقام)، وهو ضمن نطاق «جيد» (< 0.1).

## 4. فحوص وظيفية

| الفحص | النتيجة |
|---|---|
| نموذج الحجز: خطوتان، اختيار خدمة، تحقق، إرسال REST، بديل بلا JavaScript (admin-post) | يعمل |
| نموذج صفحة التواصل: رسائل التحقق المطابقة للتصميم، حفظ الشركة/الهاتف/السوق/الهدف | يعمل (طلب تجريبي حُفظ بكل الحقول) |

## 5. انحرافات مقصودة عن التصميم

| الموضع | الانحراف | السبب |
|---|---|---|
| أرقام خطوات «مراحل العمل» في صفحة سلة | الشفافية 0.5 → 0.56 و`aria-hidden` | الحد الأدنى لتباين 3:1؛ الفرق غير ملحوظ بصريًا |
| بطاقة المقال في الرئيسية | عنوان وتصنيف المقال الحقيقي بدل نص البطاقة في التصميم | المحتوى يأتي من المقالات المنشورة |
| جدول محتويات المقال | يُبنى من عناوين H2 الفعلية | يطابق المقال الحقيقي بدل نص العيّنة |
| رابط «بناء الروابط» في فوتر الرئيسية | «السيو الخارجي» كبقية الصفحات | توحيد الفوتر بين الصفحات |
| لقطات معرض دراسات الحالة | مخفية حتى التحقق | اللقطات في التصميم مكررة بين الحالات |
| زملاء عضو الفريق | الأعضاء الثلاثة التاليون بالترتيب | مطابق لمنطق التصميم |

## 6. حدود الاختبار

- القياسات على خادم PHP المدمج محليًا؛ يجب تكرار Lighthouse على الاستضافة النهائية بعد تفعيل الكاش والضغط.
- لم يُختبر إرسال البريد الفعلي (لا خادم SMTP في بيئة الاختبار).
- لم تُختبر أداة الحجز الخارجية (لم يُحدَّد مزوّد بعد) ولا Trustindex (لا كود مختصر بعد).
- المتصفح المستخدم: Chromium 141 (Playwright). يُنصح بمراجعة يدوية على Safari iOS وChrome Android.
